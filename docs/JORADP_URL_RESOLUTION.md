# حل روابط JORADP غير المستقرة

## المشكلة

الرابط المباشر لملف PDF في موقع الجريدة الرسمية الجزائرية ليس معرفًا قانونيًا ثابتًا للمصدر. أظهرت الحالات العملية أن الوصول قد يتأثر بـ:

- اختلاف حالة الأحرف في المسار (`jo-francais` مقابل `JO-FRANCAIS`)؛
- اختلاف امتداد `.pdf` و`.PDF`؛
- مسارات تاريخية قد تعمل مع عميل وتفشل مع آخر؛
- سلوك خادم غير متجانس في الوصول المباشر؛
- بقاء صفحة السنة/العدد قابلة للوصول حتى عندما يفشل رابط مباشر مسجل.

لذلك **لا يجوز حذف رابط مسجل لمجرد أنه فشل في محاولة وصول واحدة**.

## الهوية الثابتة للمصدر

يعامل المشروع المصدر على أنه هوية مركبة:

```text
JORADP : YEAR : ISSUE : LANGUAGE
```

مثال:

```text
JORADP:2018:36:ar
JORADP:2018:36:fr
```

أما URL فهو endpoint قابل للتغير للوصول إلى هذه الهوية.

## ترتيب الحل الآلي

`scripts/joradp_resolver.py` يعمل بالترتيب الآتي:

1. يجرب الرابط أو الروابط المسجلة في `sources.yml`؛
2. يولد اختلافات deterministic لحالة الأحرف وامتداد PDF؛
3. إذا لم ينجح، يفتح صفحة السنة الرسمية:
   - العربية: `https://www.joradp.dz/JRN/ZA<YEAR>.htm`
   - الفرنسية: `https://www.joradp.dz/JRN/ZF<YEAR>.htm`
4. يبحث في الصفحة عن رابط العدد المطلوب؛
5. يتحقق أن الاستجابة PDF فعلًا، لا مجرد HTTP 200 لصفحة خطأ؛
6. يعيد `resolved_url` وطريقة الحل وسجل المحاولات.

## أمثلة تشغيل

### من رابط مسجل

```bash
python3 scripts/joradp_resolver.py \
  https://www.joradp.dz/FTP/jo-francais/2018/F2018036.pdf \
  --json
```

### من سجل المصدر داخل الحزمة

```bash
python3 scripts/joradp_resolver.py \
  corpus/texts/DZ-DE-2018-162/sources/sources.yml \
  --lang fr \
  --json
```

### عندما لا يمكن استنتاج السنة أو العدد

```bash
python3 scripts/joradp_resolver.py SOURCE \
  --lang ar \
  --year 2018 \
  --issue 36
```

## الاستخراج النصي

`scripts/materialize_joradp_text.py` يستعمل الـresolver قبل تنزيل PDF المؤقت:

```bash
python3 scripts/materialize_joradp_text.py \
  corpus/texts/DZ-DE-2018-162/sources/sources.yml \
  /tmp/f2018036.txt \
  --lang fr \
  --first-page 7 \
  --last-page 12 \
  --show-resolution
```

الـPDF ينزل إلى مجلد مؤقت فقط ويحذف بعد الاستخراج. لا يدخل Git.

## ما الذي نحفظه في `sources.yml`؟

نحتفظ دائمًا بـ:

- الرابط المسجل تاريخيًا (`url`)؛
- هوية العدد: السنة والرقم؛
- الصفحات حسب اللغة؛
- رابط صفحة السنة الرسمية عند توفره؛
- `resolved_url` إذا تحقق رابط عامل؛
- تاريخ الفحص؛
- وصف نتيجة الوصول، بصياغة غير قطعية مثل `failed_in_one_automated_check` عندما يكون الفشل خاصًا بمحاولة واحدة؛
- طريقة الحل (`recorded_url`, `path_case_variant`, `official_year_index`, ...).

لا نستبدل الرابط المسجل بالرابط العامل؛ كلاهما يحمل معلومة مختلفة:

- المسجل = provenance؛
- العامل = endpoint تشغيلي حالي.

## الواجهة البشرية

يجب أن تعرض `README.md`:

1. الرابط الرسمي المسجل؛
2. الرابط العامل البديل إذا تحقق؛
3. صفحة السنة الرسمية كمسار fallback؛
4. الصفحات التي يقع فيها النص؛
5. رابط `sources.yml` للتفاصيل.

إذا لم يوجد رابط عامل متحقق، يبقى الرابط المسجل ظاهرًا مع تنبيه مناسب، ولا يخترع المشروع رابطًا.

## قاعدة للـAgents

فشل URL لا يساوي غياب المصدر، ونجاح URL لا يثبت وحده أن الملف هو العدد الصحيح. يجب مطابقة:

- السنة؛
- رقم العدد؛
- اللغة؛
- تاريخ النشر عند الحاجة؛
- الصفحة/العنوان أو النص المستهدف.

الـresolver يحل مشكلة الوصول، وليس بديلًا عن التحقق القانوني أو البصري.
